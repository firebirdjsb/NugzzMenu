# Special customers update compatibility

The current follow-up is documented in
[SPECIAL_CUSTOMERS_FIXES_20261011.md](SPECIAL_CUSTOMERS_FIXES_20261011.md).
It includes stable S1API 3.2.1, complete visiting rosters, and the subsequently
reported phone, prompt, police, clothing, and config changes. Audit counts
below labeled as the initial pass are historical evidence.

## Scope

Target: Schedule I 0.4.7f12, Steam build 25796331, the special customers update
supplied in the patch notes and the replacement DLL dump.
The menu discovers registered content rather than creating duplicate vanilla
items or NPCs. Save formats, NPC schedules, laundering rules,
cosmetic definitions, and native building placement stay game-owned.
The explicit group queue control changes visit timing through the native
`QueueCustomerGroup` method, as requested by the user.

## S1API dependency

The build reference and staged IL2CPP package use
[S1API 3.2.1](https://github.com/ifBars/S1API/releases/tag/v3.2.1).
The version, upstream download URL, and SHA-256 are pinned in `S1API.lock.json`.

Refresh the local reference and stage the matching mod/loader pair:

```powershell
python scripts/update_s1api.py
```

An existing download can be passed with `--archive <zip>`. The script verifies
the checksum, preserves the previous build reference, and extracts only the
IL2CPP mod and its loader. It does not install into a game directory. Use this
S1API package with the updated game, not the older 0.4.6 installation.

Public S1API APIs used by the menu:

- `GameLifecycle.OnLoadComplete` and `OnPreSceneChange` for lifecycle handling.
- `Entities.Player` spawn events for player/cache initialization.
- `Items.ItemManager.GetAllItemDefinitions()` for registered item IDs.
- `Entities.NPC.All`, `Transform`, `ID`, and `FullName` for NPC discovery.
- `Weather.WeatherManager.KnownSequenceIds` for weather-preset discovery.
- `GameTime.TimeManager.SetTime()` for host-controlled time changes.

These public APIs are resolved at runtime so a missing optional surface does
not stop the menu from loading. Native registries supplement S1API discovery,
including visitors that lack a named API wrapper. Inventory quality/color
factories and weather changes use the game's APIs; S1API's weather API is
read-only. No S1API internal fields are accessed.

## First pass: content and lifecycle

- The item catalog uses `ItemDefinition.ID`, rather than assuming a Unity asset
  name is its registry ID. Inventory quality matching and mixture lookup use
  the same identity.
- Runtime registrations, removals, and definition replacements refresh the
  catalog at a two-second interval. Search, filters, page, and mixture selection
  survive this refresh.
- Clothing definitions remain explicitly eligible for the item catalog.
- The people list merges the S1API and native NPC registries, deduplicates live
  instances, and refreshes while the Relationships tab is open.
- Selection survives refresh by NPC ID. Despawned or failed-scan targets cannot
  leave a different person selected for an edit.
- Item/NPC caches and queued inventory spawns reset on scene changes, including
  returning to the menu and loading another save.
- NPC names/IDs can be read from the new `NPCData.BasicInfo` surface while still
  supporting the old native identity members.
- Affinity reads support the property accessors generated by IL2CPP, so an
  existing affinity is not mistaken for the customer's default affinity.

## Second pass: compatibility bindings

- The old avatar accessory guard is optional and resolves its target at runtime.
  It has no hard reference to `ApplyAccessorySettings` or `AvatarSettings`.
- The new guard targets `AvatarAppearance.ApplyAvatarObject`. It identifies the
  crown using the registered clothing definition's `ClothingAvatarObject.Id`,
  rather than guessing its new object ID. Both guards share the same exception
  classifier and rate-limited diagnostic.
- Character-creation input gating uses the relocated `CharacterCreator` type.
- Player visibility uses `SetThirdPersonMeshesVisibility`; third-person yaw uses
  the current `PlayerMovement.SetRotation` wrapper. Scale correction reads foot
  anchors from the avatar's attachment provider.
- Time changes use public S1API `SetTime`, with `SetTime_Server` only when the
  API method is unavailable. Trash creation uses its current five-argument API.
- Spray-bottle fallback reads the generated water/prefab properties and calls
  native `CanSpray` directly. NonPublic-only reflection did not find the public
  IL2CPP wrappers and silently skipped those operations.
- Held-item fallback reads the generated `Equippable.itemInstance` property.
  Hovered interaction containers are resolved from their generated properties
  before searching neighboring objects.
- The NPC enter-animation wait guard resolves its parameterless predicates by
  method shape rather than a compiler-generated lambda number.
- Initial police siren synchronization hooks `VehicleLights.Awake` instead of
  the generator-specific `Method_Private_Void_PDM_0` alias.
- A metadata audit checks compiled game type/member bindings, attribute-based
  Harmony targets, the public S1API contracts, and required 0.4.7 markers.

## Deployment and rollback

No game DLLs, saves, Steam configuration, or published releases were modified
by this work. The user updated/launched the game to regenerate references. The
previous S1API build reference is preserved under
`trialbuild/s1api/<version>/backups`. Install a tested menu DLL and the matching
S1API mod/loader pair together for a controlled test with the game closed.
Keep the previous three DLLs outside the Mods/Plugins folders. Rollback restores
that previous mod set with the game closed; an old mod set can still be
incompatible with 0.4.7. No save-format migration is introduced by this change.
